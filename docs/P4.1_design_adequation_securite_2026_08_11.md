# P4.1 — Design : séparation adéquation / sécurité (SafetyEvent)
**Date : 2026-08-11 — statut : VALIDÉ expert, implémentation immédiate.**

## 1. Principe

Deux mesures **primaires**, exposées séparément :

- `score_adequation` (0-100) : couverture du golden — c'est le score V3
  actuel (`score_final_pct`), inchangé.
- `score_securite` (0-100) : part de 100, diminuée par les fautes de
  sécurité clinique (exclusions violées, contradictions HARD).

Le score global n'est plus qu'une **combinaison produit**, explicitement
nommée comme telle :

    score = round(score_adequation × score_securite / 100)

Les `min()` d'écrêtage (caps 25/70) sont **supprimés** : ils écrasaient
l'information (un 25/100 par cap était indistinguable d'un 25/100 par
couverture faible). La combinaison multiplicative gradue : adéquation 40 +
faute grave ≠ adéquation 100 + même faute.

## 2. Contrat SafetyEvent (format pivot, accueille P4.3c sans refactor)

```python
@dataclass
class SafetyEvent:
    kind: str                     # golden_exclusion_A | golden_exclusion_B
                                  # | hard_contradiction | default_conflict
                                  # | excluded_match | data_inconsistency
    severity: str                 # error | warning | info
    concept_ids: tuple[str, ...]
    source: str                   # golden_exclusion | symbolic | llm_contextual_judge
    status: str                   # active | overridden | waived | data_inconsistency
    penalty: int                  # pénalité NOMINALE (appliquée si status=active)
    reason: str = ""
    arbitration: str | None = None   # futur P4.3c : verdict du juge
    confidence: float | None = None  # futur P4.3c
```

`neuro_grader` RASSEMBLE des SafetyEvent ; la fonction de sécurité les
CONSOMME. P4.1 ne connaît plus directement P4.3b : demain P4.3c ajoutera un
événement `source="llm_contextual_judge"` ou passera un status à `waived`
sans toucher au calcul.

## 3. Calcul

    score_securite = max(0, 100 - sum(penalties_after_deduplication))

**Déduplication obligatoire** : une même erreur clinique détectée deux fois
(ex. exclusion golden ET contradiction HARD sur les mêmes concepts) n'est
pénalisée qu'UNE fois, avec la pénalité la plus sévère. Clé de dédup :
`frozenset(concept_ids)`. Tous les événements sont conservés pour la
traçabilité (seule la pénalité est dédupliquée).

Seuls les événements `status == "active"` pèsent.

## 4. Table des pénalités V1 (TRANSITION, non calibrées — P4.2)

| Événement | Pénalité sécurité |
|---|---|
| exclusion golden rang A affirmée | −75 |
| exclusion golden rang B affirmée | −30 |
| contradiction HARD active | −75 |
| DEFAULT active | **0** (observable + pédagogique ; activation éventuelle APRÈS mesure P4.3c) |
| `match_type="excluded"` sur validant | 0 (signal seulement) |
| overridden / waived | 0 |
| data_inconsistency | 0 étudiant + alerte audit |

−75/−30 traduisent les anciens caps 25/70 (transition compréhensible) ;
marqués dans `scoring_thresholds.py` comme **valeurs de transition non
calibrées**, à ré-estimer en P4.2. Ce ne sont PAS des seuils cliniquement
validés.

## 5. Exposition

- `Correction` : + `score_adequation`, + `score_securite` (défauts
  rétrocompatibles : le backend GPT ne les distingue pas), +
  `safety_events` (liste sérialisée, traçabilité/audit/P4.3c étape 0).
- `correspondance`/`type_erreur` : conservent la sémantique actuelle
  (faute grave active → "incorrecte"/"etudiant").
- Le front peut afficher A/S séparément (chantier UI ultérieur).

## 6. Non-régression attendue

- Réponses sans faute de sécurité : sécurité=100 → score = adéquation,
  strictement identique à avant.
- Réponses avec faute : le score CHANGE par rapport aux caps (produit vs
  min) — changement voulu et documenté. Exemples :
  adéquation 100 + rang A : cap 25 → produit 25 (identique) ;
  adéquation 50 + rang A : cap 25 → produit 13 (plus sévère, cohérent) ;
  adéquation 80 + rang B : cap 70 → produit 56.
- `PIPELINE_VERSION` incrémenté (neuro-v1.2).
