**Conséquence clé** : la règle « max 5/cas » sur 50 cas donne **190 copies**,
pas 75. Trois options de volume pour l'annotation :

- **(a) 190 copies (~5-6 h)** : couverture maximale, calibration robuste ;
- **(b) 5/cas sur les 29 cas ≥5 réponses ≈ 145 copies (~4-5 h)** : évite
  les cas à 1-2 réponses (peu informatifs pour la stratification) ;
- **(c) plafond global 75 copies (~2h30, budget v1)** : 2-3 copies/cas sur
  les ~30 cas les mieux fournis — reste suffisant pour la validation
  globale, plus fragile pour l'analyse par cas.

**Recommandation : (b)** — bon ratio information/effort ; les 21 cas à
<5 réponses entrent quand même dans le REJEU (non-régression + log P4.3c),
seule l'annotation les saute.

## 3. Cible d'annotation (décision expert v1 maintenue)

Note globale /10 par copie, en aveugle (sans le score machine) **+
questionnaire ~10 items abstraits** calibrant directement les crédits
partiels (« “bloc de branche” quand le golden attend “BBG” : /10 ? »).
Les notes globales VALIDENT, le questionnaire ESTIME → pas de boîte noire.
Expert unique ; contrôle intra-expert : 10 copies ré-annotées à ≥1 semaine.

## 4. Protocole A-E révisé

- **A. Ingestion + rejeu** : script qui lit l'onglet `reponses` du Sheet
  (accès service account déjà fonctionnel, cf.
  `scripts/_read_new_sheets_2026_08_11.py`), déduplique par `response_id`
  (et garde la DERNIÈRE tentative par session×cas — champ `tentative` /
  `refait` à examiner), puis rejoue les ~579 réponses avec neuro-v1.2.
  Produits : `data/p42_corpus_rescored.json` (score, adéquation, sécurité,

  (P4.3c : fréquence réelle des paires sur 579 réponses de production —
  le critère d'abandon <1 % devient mesurable immédiatement).
- **B. Échantillonnage stratifié** : 5 copies/cas sur les 29 cas ≥5 rép.
  (1 basse / 2 moyennes / 1 haute / 1 aléatoire, sur le score machine du
  rejeu) → ~145 copies → feuille d'annotation CSV EN AVEUGLE
  (`cas, copie_id, texte, note_expert_/10, commentaire`).
- **C. Annotation expert** (~4-5 h, sécable par sessions de 30 cas) +
  questionnaire crédits (15 min). Complément golden : plus urgent pour les
  50 cas jamais répondus (hors corpus) que pour le corpus lui-même —
  découplable de P4.2.
- **D. Analyse** : Spearman + Lin CCC global et par cas ; top-10 résidus
  (diagnostic : NER / golden incomplet / crédit) ; ajustement des crédits
  d'après questionnaire ; re-scoring → la corrélation doit s'améliorer.
- **E. Verrouillage** : `scoring_thresholds.py` avec mention « calibré
  P4.2, N copies, date » ; challenge set + garde-fous ; bump
  `PIPELINE_VERSION`.

## 5. Points d'attention spécifiques à ce corpus

1. **Doublons/tentatives** : champs `tentative`, `refait`,
   `reponse_initiale`/`reponse_modifiee` → définir la règle AVANT le rejeu
   (proposition : garder la dernière soumission par session×cas ; les
   paires initiale/modifiée sont un bonus d'analyse, pas des copies
   distinctes).
2. **20 réponses backend `gpt`** : à exclure de la calibration (autre
   correcteur) mais à garder dans le rejeu.
3. **Queue longue** (13 cas à 1-2 réponses) : hors annotation, mais
   incluses dans le rejeu.
4. **`par_cas` (76 lignes)** est une VUE agrégée de `reponses` — source de
   vérité = `reponses`, ne pas ingérer les deux.
5. Réponses très courtes (« inversion electrode ») : légitimes (fragments
   cliniques), ne pas filtrer sur la longueur.
