## Décision complémentaire : SYMÉTRIE des conflits

La liste actuelle duplique certaines directions (#1/#2, #14/#15…) et en
omet d'autres (#13 HYPONATREMIE→HYPERNATREMIE absent, #33, #47…). Cette
asymétrie est dangereuse : tôt ou tard une direction sera ajoutée sans
l'autre.

**Règle retenue** :
- `excludes` et `conflicts_by_default` sont **symétriques par définition** :
  le moteur canonicalise `pair = tuple(sorted((A, B)))` — une seule
  déclaration suffit, la réciproque est implicite ;
- `requires`, `implies`, `negation_of` restent **directionnels** ;
- audit CI (ou script de vérification) exigeant la cohérence.

## Plan AMENDÉ — P4.3a-bis AVANT la migration

1. **Corriger les 12 relations fausses** (suppression) — script dédié,
   backup + dry-run ;
2. **Séparer `negation_of` de `excludes`** dans `build_negation_map()`
   (les paires #1-4 sont des négations, pas de simples exclusions) ;
3. **Définir la symétrie des conflits** dans le moteur
   (canonicalisation `sorted pair`) + compléter les réciproques
   manquantes (ou les rendre inutiles par la canonicalisation) ;
4. **Introduire ACCEPTED / FORBIDDEN / UNKNOWN** pour le statut d'un
   concept vis-à-vis du golden d'un cas (nécessaire pour l'override :
   `golden_accepts(A, B)` = les deux ACCEPTED) ;
5. **Ensuite seulement** : migration HARD (13) / DEFAULT (24) via
   `migrate_excludes_to_conflicts` ;
6. P4.3b : moteur — vérification intra-réponse avec override golden.

Principe conservé : **le Python ne connaît aucune cardiologie** — toute
la connaissance reste dans l'ontologie et le golden.
